# Project instructions

## `src/Service/MenuVisionPromptBuilder.php` is FROZEN

Do not edit this file's prompt text for any reason — including a change that looks trivially small (one sentence, one rule, no new fields) — without first creating a golden fixture that exercises the new behavior, then iterating the prompt change against **all** golden fixtures (`tests/fixtures/*.expected.json` via `tests/VisionEval`) until they pass.

**Why:** verified twice in one day (2026-07-17/18) that even minimal prompt additions regress unrelated goldens:
- A deliberately mechanical, narrowly-scoped glass/bottle-price rule caused the model to start extracting ingredients from parenthetical lists in dish names (Elian golden).
- A single plain sentence about picking the rightmost price column caused the model to stop stripping a trailing parenthetical from a dish name that the golden requires stripped (Elian golden, "Ensaladita de ventresca de atún").

Neither regression was predictable from reading the added sentence in isolation — prompt changes here have non-local effects on unrelated rules, even when the wording is careful, mechanical, and scoped.

**How to apply:** before writing a new rule or editing an existing one in this file:
1. Create/extend a golden fixture (image + `.expected.json`) that specifically exercises the new behavior — don't rely on existing goldens to happen to cover it.
2. Make the prompt change.
3. Run `tests/VisionEval` (real API calls, costs money, not part of the default suite — see its own docblock) against **every** golden fixture, not just the new one.
4. If any golden regresses, revert the prompt change immediately (`git checkout HEAD -- src/Service/MenuVisionPromptBuilder.php` if uncommitted) rather than trying to patch around it — patching one regression while adding another rule tends to compound the instability, per the two incidents above.

Never commit a change to this file that hasn't cleared step 3 against all goldens.
